Two problems, one design decision each

Pick the approach for each — they're independent

Problem 1 — Token efficiency & speed
A

Client-side pre-processing + targeted LLM

Extract keywords from JD in the browser (JS, zero tokens). Score blocks by keyword overlap — only send relevant blocks to Gemini. Strip LaTeX boilerplate before sending, reapply after.

Pros

  • ~60–70% fewer tokens
  • Faster (smaller payloads)
  • Better quality — LLM focuses only on relevant blocks

Cons

  • Still uses LLM for rewrites
  • Keyword extractor needs some tuning
B

Two-mode: instant highlight + optional LLM rewrite

Default flow: client-side only — extract keywords, score blocks, highlight gaps, auto-update skills section. LLM rewrite is opt-in per block via a "rewrite with AI" button.

Pros

  • Instant results for the common case
  • Zero tokens unless you click rewrite
  • Granular control over what gets rewritten

Cons

  • More UI work
  • Per-block rewrites are smaller prompts but more round-trips
Problem 2 — PDF export
A

LaTeX compile API → direct PDF download

Send the assembled .tex to a free LaTeX compilation API (e.g. latexonline.cc). Get a PDF blob back, trigger browser download. Pixel-perfect match to your resume template.

Pros

  • Exact same output as Overleaf
  • One-click download, no copy-paste
  • No layout maintenance

Cons

  • ~5–15s compile time
  • Depends on external free service
  • May fail if service is down
B

HTML resume mirror + browser print-to-PDF

Build a styled HTML version of the resume that mirrors the LaTeX layout. "Download PDF" triggers window.print() with @media print CSS — browser exports it as PDF natively.

Pros

  • Instant, no external service
  • Works offline
  • Preview in-app before export

Cons

  • HTML layout ≠ LaTeX exactly
  • Browser print dialog (not seamless on all browsers)
  • Need to maintain HTML template alongside LaTeX blocks
C

Both — HTML preview + LaTeX API download

Render the resume as HTML live in the app (instant preview as you toggle blocks). "Download PDF" button calls the LaTeX API for the pixel-perfect version. HTML preview doubles as a fast visual check before compiling.

Pros

  • Best UX — see changes live, download when ready
  • API failure falls back gracefully to copy .tex

Cons

  • Most work to build
  • HTML and LaTeX can drift if blocks are edited
